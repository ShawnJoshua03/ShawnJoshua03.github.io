## The Problem

Coding agents are getting good at working in parallel, and Claude Code can already lead a team of them. The weak point is permission. A worker asks to run a command or write a file, and something has to say yes. If the lead model says yes, the safety of the whole setup is the safety of that model's prompt.

## What I Built

A local MCP server where Claude Code is the lead engineer and the other agents are bounded workers. Each worker gets its own git worktree on a new branch, a filtered environment and a hub-owned home directory, so it never touches your checkout or another worker. Every risky action it asks for becomes one human decision on the exact request, or an error.

The flow is `start_worker`, `wait_for_worker`, `get_worker_diff` and `commit_worker_changes`, then you merge. The hub only ever commits to the worker's own branch, and it stores every request, decision and state change in SQLite so you can read the audit trail afterwards.

## How It Works

<ol class="pipeline">
  <li><b>Isolate</b><span>The hub makes a worktree, filters the environment and gives the worker its own home. It pins the git directory it recorded and disables hooks, so a worker that rewrites <code>.git/hooks</code> or its <code>.git</code> pointer gains nothing.</span></li>
  <li><b>Check the setup</b><span>Each adapter reads back the provider's effective permissions, MCP servers and approval mode, and stops before any model call if they differ from what it asked for. It fails closed on drift.</span></li>
  <li><b>Show the real action</b><span>A permission prompt is forwarded to the human only if it carries the exact command or diff. Gemini CLI's shell prompt can carry a model-written description instead, so the hub refuses those.</span></li>
  <li class="out"><b>Decide and record</b><span>The human answers an MCP form in the client. Allow works once. Deny stops the task. Both are written to the audit log.</span></li>
</ol>

The threat model lists each attack, the defence and the test for it, and says what remains. The most useful finding was that ACP permission prompts are not a uniform trust boundary: the same protocol shows the real command from one agent and a paraphrase from another.

## Limitations

- **Three workers are unverified against their real CLIs.** Gemini CLI, Grok and OpenRouter pass tests against simulated agents only. The Gemini key on the development machine was rejected by Google, and Grok has no non-interactive login.
- **Phone approval does not work.** Claude Remote Control paired with an iPhone, but the approval forms never rendered there. Approvals happen in the desktop or terminal client.
- **Only Codex runs in an OS sandbox.** Once you approve an action for OpenCode, Gemini or Grok, it runs as you.
- **Windows first.** Process cleanup uses `taskkill`, and the tests have not been run on other platforms.
- **Pinned to today's CLIs.** Checks fail closed on drift, but expect to re-verify after upgrades.
- **Symlink refusal has no dedicated test.** Local models through Ollama are not supported, on purpose.
- **A feasibility pilot, not a product.**
