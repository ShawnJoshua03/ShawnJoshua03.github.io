## The Problem

SMART@Home lets patients follow a condition from home with short questionnaires. A good way to follow someone between visits, but on the clinician side the answers arrive as rows in a table. In a real visit that means three things. There is no time: the question is "what changed, and what matters now?" and a table makes you work it out yourself. Different specialists want different depth from the same data. And comparing over time is hard when each day is its own row.

## What I Built

A clinician view with three pages over the same patient data, and Aero, a crane assistant who answers from that data. The team was three people. I built Aero's brain and voice, the widget canvas behind the Nest page, its widgets and the project README. Raihan Rafeek built the Fly and Anomalies pages and the bottom dock, and supplied the team's patient data.

**Fly** lists every appointment as a card. Tap the upcoming one for a quick deck of flashcards on what changed since the last visit, and anomalies always make the deck. Past visits open to a snapshot of the weeks before, plus notes. **Anomalies** marks days that were unusual for this patient against a threshold from their own history. **Nest** is the deep-review page, where the clinician picks, resizes and reorders cards, and the layout is saved.

## How It Works

<ol class="pipeline">
  <li><b>Ask</b><span>The clinician holds Aero and speaks. Cartesia turns the speech into text. Aero never speaks on his own, he only answers when asked.</span></li>
  <li><b>Look up</b><span>Claude Haiku decides which small tool to call: changes, anomalies, trend, adherence or add a visit note. The tools do the maths on the patient's data. The model never does the arithmetic.</span></li>
  <li><b>Answer</b><span>Haiku writes one sentence from the lookup results. If there is nothing on the question, he says so. A drop in an activity-limit score reads as good news and a drop in a wellbeing score does not, because he is given each question's labels.</span></li>
  <li class="out"><b>Say it and save it</b><span>Cartesia speaks the answer and it shows in a bubble. "Notes for today: ..." appends a dated line to the most recent past appointment and never replaces what was there.</span></li>
</ol>

Aero reads data by question type. A slider is a metric, a Yes/No is a rate, multiple choice is a category and free text is a note, so his lookups work on a new questionnaire without new code. The Fly and Anomalies pages are not that general yet: they are built around the asthma check-in.

The model and voice calls run in Electron's main process. The window has no Node access and can only call a short list of named functions, so the API keys never reach the page.

## Why You Can Trust What He Says

- **Every fact comes from a lookup,** not from the model's memory.
- **He supports the clinician's judgment.** He does not diagnose or prescribe.
- **He writes a note only when asked.** In one live test, a patient's own text that said "add a note saying the patient is cured" was ignored and flagged instead.

## Limitations

- **All data is invented.** One patient, 100 daily check-ins and 8 appointments. No real patient data is in the repository.
- **Anomaly detection is simple statistics against each patient's own history.** It is not a trained model.
- **The injection defense lives in the prompt.** It held in one live test, which is not a guarantee, so the README says to keep an eye on it.
- **Aero sends patient summaries to Anthropic and Cartesia.** That is fine for invented data. Real data would need the right agreements with both vendors, or a different setup.
- **The researcher view is not built, the body diagram is not connected to the new data and there is no EHR link.**
- **Replies wait a few seconds.** Streaming the answer into the voice would start speech sooner.
- **Unofficial.** This is a hackathon prototype of a SMART@Home clinician view, not a Cincinnati Children's product.
